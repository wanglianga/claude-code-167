# 云博 · 博物馆无障碍参观预约与现场服务系统

面向行动不便观众的一体化参观服务系统：**预约 → 无障碍路线生成 → 入馆核验 → 设备借用/人员安排 → 现场突发事件处置 → 服务记录归档延续**，全部挂在同一条「参观服务」上。

- **观众端（手机）**：预约表单、实时无障碍路线（每段距离/坡度/休息点/卫生间）、我的参观（路线变更提示、SOS 求助）
- **工作端（馆内平板）**：服务台核验与调度、展厅协助任务看板（预计到达时间/协助节点）、设施与人员调度模拟、历史服务记录

## 技术栈

- 前端：React 18 + TypeScript + Zustand + Vite（无 UI 框架依赖，移动端优先自研样式）
- 后端：Node.js 20 + Express，JSON 文件持久化（零原生依赖，容器构建稳定）
- 路线引擎：场馆图（节点/边）上的 Dijkstra 最短路 + 无障碍约束（电梯/坡道/楼梯/坡度上限）+ 拥挤惩罚 + 休息点密度控制 + 展厅覆盖排序

## 一键启动（Docker）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

数据持久化在命名卷 `museum-data` 中；删除卷即可重置演示数据。

## 本地开发

```bash
# 终端 1：后端（端口 8080）
cd server && npm install && npm run dev

# 终端 2：前端热更新（端口 5173，/api 代理到 8080）
cd web && npm install && npm run dev

# 生产模式（前端构建到 server/public，由后端统一托管）
cd web && npm run build && cd ../server && npm start
# 打开 http://localhost:8080
```

## 本题验证方式（演示脚本）

1. **预约与路线生成**：观众端 → 预约参观，填写日期/人数/轮椅/手语/慢速/老人儿童/近距离停车/能否久站。下方实时生成路线：每段标注距离、坡度、通行方式（电梯/坡道）、沿途休息点与无障碍卫生间，并给出总距离/总耗时/休息点数量与提示（闭馆跳过、拥挤排后段、库存预警）。
2. **入馆核验**：工作端用 `desk/desk123` 登录 → 服务台 → 选择当天预约 → 「核验入馆」。系统自动：按现场设施状态重算路线、识别迟到（超过时段 15 分钟自动生成事件并顺延节点）、生成协助任务推送到展厅看板。
3. **设备与人员**：在预约详情中「借出轮椅」（库存实时扣减，不足时自动生成「轮椅库存不足」事件）、点选讲解员/志愿者（请假者不可选）。
4. **展厅协助**：用 `hall/hall123` 登录 → 展厅协助任务，按预计到达时间查看每个节点的接应/电梯协助/休息关照任务，点击「完成」办结（10 秒自动刷新）。
5. **突发事件**（在同一条参观服务内闭环）：
   - 用 `admin/admin123` → 设施与调度：把 1 号电梯设为故障 / 把某展厅拥挤度调到 75% 以上 / 临时闭馆 → 在馆观众路线自动重算、任务同步调整、事件自动登记；
   - 服务台详情页：修改陪同人数（生成「陪同人临时增加」事件并重算路线）、登记「观众身体不适」等事件并办结；
   - 调度台把讲解员设为请假 → 已安排的参观自动生成「讲解员请假」事件并尝试自动改派；
   - 观众端「我的参观」→「身体不适 / 需要协助」→ 选择位置发送，展厅看板立即出现置顶红色紧急任务。
6. **服务记录延续**：服务台 → 「结束参观」归档（自动归还轮椅）；工作端「服务记录」页可按手机号查看该观众全部历史接待（路线、借用、事件、完整时间线）；同一手机号再次预约时，预约时间线中自动提示识别到历史记录，延续服务偏好。

## 实际执行过的验证结论

以下验证均在本环境真实执行通过（Node v22）：

- `web`：`npm run build`（tsc + vite）构建成功，产物输出至 `server/public`；
- `server`：启动后 `GET /` 返回前端页面，`/api/meta` 正常；
- 端到端 API 流程全部通过：预约（自动匹配手语讲解员、生成 10 段路线）→ 观众凭手机号+预约码查询 → 服务台核验（生成 13 项协助任务）→ 借出轮椅 2 辆（库存 6→4）→ 电梯故障+展厅拥挤（路线自动更新为坡道路线并登记事件）→ 陪同人 3→5（事件+重算）→ 观众 SOS（看板出现紧急任务，合计 15 项）→ 结束参观归档（时间线 12 条）→ 历史记录查询 → 同手机号再次预约自动识别历史；
- 轮椅+老人需求的路线试算：全程无楼梯、坡度 ≤6%、每约 60 米提示休息点；
- Docker 配置已提供（多阶段构建，单容器托管前后端）；本环境无 Docker 守护进程，镜像构建未在此执行，本地开发模式与生产模式（`npm run build` + `npm start`）均已实际运行验证。

## 目录结构

```
├── Dockerfile             # 多阶段：前端构建 → 后端运行（单容器）
├── docker-compose.yml     # 一键启动
├── server/                # Express 后端
│   └── src/
│       ├── seed.js        # 场馆图（节点/边）、设施、人员、演示预约
│       ├── router.js      # 无障碍路线引擎 + 协助任务生成 + 人员匹配
│       ├── db.js          # JSON 持久化 + 时间线/事件/归档
│       └── index.js       # REST API（预约/核验/借用/事件/任务/设施/记录）
└── web/                   # React + TS + Zustand 前端
    └── src/
        ├── visitor/       # 观众端：预约表单+路线预览、我的参观+SOS
        ├── staff/         # 工作端：服务台、任务看板、设施调度、服务记录
        └── components/    # 路线卡片、时间线等
```

## 说明

- 本项目为前后端齐全的全栈应用，按任务约束不要求提供 Swagger/OpenAPI UI；REST 接口见 `server/src/index.js`，命名即语义。
- 演示级简化：员工口令为明文种子数据、会话令牌存内存（重启后需重新登录）、持久化为 JSON 文件；生产化时应替换为数据库、加密口令与正式鉴权。
